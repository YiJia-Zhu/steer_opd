## 4. P1：逐题缓存与方向版本保存

以下为新版待实现的数据契约，不表示已生成这些文件。缓存可采用分片加索引，无须每题单建目录；
无论文件组织如何，都必须能按题目ID找回文本与当时实际使用的方向。

| 保存对象 | 最小字段 | 复用与版本规则 |
|---|---|---|
| 题目索引 | question_id、source/index、题干及hash、split、prompt token/hash | 内容变化必须换版本，不能仅以行号关联 |
| T/R参考文本 | 模型/revision/模式、生成参数与seed、文本/编码、正文mask、完成/截断/过滤状态、hash | 固定文本可跨轮复用；teacher参考回答不替代学生前缀概率评分 |
| S自身bootstrap | student_checkpoint_id、无hook生成协议、文本/编码及hash | T−S/R−S在线对照额外生成；初始文本缓存明确另列 |
| 提取记录 | extraction_id、question_id、student_checkpoint_id/更新步、参考hash、层、模板、池化/mask协议、dtype | 两端必须由同一checkpoint读取，提取无hook/no_grad |
| 方向产物 | 每题原始差分、范数、归一化方向、校准尺度、近零/有效标志、vector_id及文件hash | 同题多层/多轮不能覆盖；保留未归一化差分供全局均值对照 |
| 本批绑定 | rollout_batch_id、行为学生版本、question_id到vector_id映射、提取策略/刷新频率 | 同批同题多个rollout共享向量；整批提交提取后再生成 |
| rollout/评分 | trajectory_id、prompt/响应token、vector_id、门控mask、行为/候选log-prob与ID、教师评分及mask | 记录实际采样分布，loss支持与门控支持分开 |
| 更新断点 | 模型/优化器/RNG、已提交更新步、采样顺序/数据游标、文本/向量/轨迹索引、配置hash | 原子提交，只恢复同一配置与产物绑定 |

不要求保存所有逐tokenhidden states：保存池化表示或原始差分，以及实际注入的归一化向量即可，
所选存储精度须能满足生成/重放一致性容差。T/R文本复用不意味着当前学生的激活也可以复用。
向量文件与mask必须留到相应更新提交，并满足约定的可审计保留规则；不能在恢复前提前删除。

失败/恢复语义：文本生成成功即逐条落盘；本轮提取以临时文件原子提交；rollout引用已提交vector_id。
若更新未提交而轨迹已生成，恢复同一个行为学生断点、同一向量与mask完成本次更新。
只有显式废弃并另记该批轨迹后，才能从别的学生版本重提/重采样，不能静默换训练条件。
checkpoint存在不等于已完成该步，仍核对process退出、产物完整性、索引/hash与更新提交状态。

## 5. P2：当前学生逐题提取及公平对照

每轮开始先固定`S_theta_k`，设eval/no_grad并关闭全部steering；每题读取T/R两份参考，
按正文mask分别池化，同层相减，保存原始差分与单位向量。本批同题去重后只提一次，
n4等多个rollout共用同题向量；参数在提取和采样期间不更新，下一轮才使用新学生重提。
向量层/尺度/归一化与注入接口一致；hook位置为block输出，首回答预测边界纳入验收。

T−R主方向不需要S自身回答。在线T−S/R−S先用本轮无hook学生生成bootstrap，再读取差分，
之后另采受控轨迹；不能用受控轨迹反向定义它自己的方向。缓存S0回答明确标为固定文本变体。
三方向比较同题、同文本/过滤、同提取者checkpoint、层和权重；原始差分逐题满足
`d(T−S)=d(T−R)+d(R−S)`，归一化后不要求等式。不同学生hidden states不可直接相减。

粒度与刷新分开验收：

1. 同一S0、相同OPD题与T/R文本：原始差分均值后归一化，得到同数据全局方向。
2. 还是同一S0与文本：保留各题独立方向，得到逐题固定缓存；与上项比较粒度。
3. 同题文本固定：每轮当前学生重提；与逐题缓存比较刷新收益及成本。
4. 独立训练提取集的全局固定作为迁移对照；周期刷新作为低优先级变体。
5. 固定提取者比较本题向量/随机另一题向量，保持向量集合、范数、层与注入协议一致。

验证batch顺序置换不改变题目到方向的对应；不同题同batch/packing不能串向量；同题多个样本
引用相同本轮产物；缓存命中必须检查checkpoint与文本hash，不能只检查question_id。
同题方向随学生漂移仅是诊断，在线版是否值得仍由无steer学习收益及实际总成本判断。

## 6. P3：门控生成与因果学习重放

先在逐题固定向量、已知mask下验证生成/重放一致，再接当前学生提取与动态门控。
每个token预测前由当前学生前缀取得教师q_t；学生probe当前步关闭注入、保留历史受控KV，
计算`O_t=|Top16(probe) intersect Top16(T)|/16`，`g_i,t=1[O_t<tau_O]`并停止梯度。
主门控不叠加熵差、不用连续强度或可学习控制器，阈值由训练侧/独立dev选定后固定。

触发时从同一旧KV快照重算正式注入前向，使用本题本轮`v_i,k`；probe上层KV不能污染正式分支。
从正式受控分布采样，保存token、实际行为概率与mask。教师在学生前缀上逐token评分，
缓存的完整教师解答仅用于提取方向，不能代替这些概率。

学习前向重放相同轨迹、向量与历史干预；对本题参考读取过程、向量、门控和教师均不反传。
首token预测状态在prompt末位，后续对应t−1；padding/packing和backward重算也要保持同题向量/mask。
逐步对照teacher-forcing的logits、采样log-prob与有效位置；无hook/alpha0/移除恢复作为基础验收。
教师前缀缓存也须隔离；同参数一致性容差由明确数值检查给出，不以平均overlap一致代替。

fresh rollout、首版ppo_epochs1；本批即使有内循环也不更换向量/门控，记录行为策略陈旧。
此surrogate只在固定访问状态上更新，不声称包含状态分布或方向提取对参数的完整导数。
g=0仍有OPD监督。滞后门控、只在loss/rollout注入或末尾修复均单列，不混为默认2–2–2。
