# 静态overlap注入协议

下一配对已选Qwen3.5-35B-A3B（T）/Qwen3.5-0.8B（Ref）→Qwen3-4B（S），见[新配对建议](13_next_pair_greedy_search_proposal.md)。
下文原生Top16集合交集与直接同token前缀评分要求可比token语义，不能在新配对未验收tokenizer时直接照用整数ID。
新配对先定义同可见文本前缀的共同概率事件，再冻结对应静态指标/mask；完成源评分后固定mask、不再在线重判的原则不变。

2026-11-13用户决定：动态逐token门控开销过大，当前改用静态overlap；相关实验和文档以本协议为准。
本次只同步计划、接口边界和记录字段，未改生成/训练源码、旧配置、模型权重，也未启动GPU或新搜索。
旧动态代码和已发生的耗时/失败结果保留为历史证据，不是当前主方案的前置任务。

## 1. 当前流程

1. 冻结本轮学生checkpoint，关闭steering，批量生成源回答y_src；rollout直接保存每个预测位置的原始Top16和log-prob。
2. rollout结束后，教师在完全相同的学生token前缀上批量teacher forcing评分，保存教师自身Top16及训练所需的候选分数。
   这里的“判分”是逐token概率评分，不是只判最终答案对错，也不是让教师另写一份回答。
3. 对源回答全部有效预测位置计算静态Overlap@16，并一次性冻结mask：

   `O_src[t] = |Top16(S(.|x,y_src[:t])) ∩ Top16(T(.|x,y_src[:t]))| / 16`

   `g_static[t] = 1[O_src[t] < tau_O]`

4. 当前零更新搜索在同一个源回答前缀上，分别做无hook基线与按固定mask注入的前向，比较即时DeltaOverlap。
   这一步是固定前缀重放，不需要再自由生成一遍回答，也不做参数更新。
5. 注入后可重新测量overlap作为结果，但不据此修改本条mask、不再插入当前步probe/教师交互。
   所有候选在相同checkpoint/源回答/阈值下复用同一份静态位置表。

每一处O_src只读取该位置之前的token；整条mask在源rollout完成后形成，属于离线生成的固定计划。
学生更新或源回答改变时需要新mask；不能把S0的静态值当成更新后学生或另一条轨迹的实时overlap。

## 2. mask在后续哪个阶段生效

已生成的源回答不会被事后注入改变。当前已经确定的是零更新固定前缀诊断；后续OPD需明确以下阶段之一：

| 使用方式 | 实际行为 | 概率与成本边界 |
|---|---|---|
| 同源回答固定前缀重放（当前搜索） | 源回答不变，在前向中使用固定mask比较有/无SV | 无额外自由生成，可批量评分，不能称为生成期已受控 |
| 只在同源回答的学习前向注入 | 行为rollout无SV，带梯度前向有SV | 属于learning-only；行为与学习条件不同，不能直接沿用“同策略同mask”的PPO声明 |
| 用已知mask再生成受控回答 | 先生成源回答定位置，再按绝对位置表生成新回答 | 可用EasySteer位置selector；额外一轮生成，新前缀上的实时overlap可能不同 |

用户尚未选择后续学习注入阶段时，不自动新增二次rollout，也不将主训练静默改成loss-only。
当前代码对阶段不同的任务要求显式candidate_rkl状态重放目标；普通参考surrogate不能仅换标签就运行。
阶段与目标确定后，八方案、相同信息、采样条件和训练预算应匹配，不能把不同阶段混作只比较gate的消融。

二次生成采用静态位置表时，不因新overlap变化更新mask。源回答范围以外默认不注入并记录覆盖率，
新回答正常EOS后结束；不能将源回答的教师分数当作新回答不同前缀上的OPD监督。
这个方案的名称是“源rollout静态位置注入”，不称为精确在线overlap门控。

## 3. EasySteer能支持什么

已核对固定版本支持逐请求`ApplySpec(generation_positions=[...])`和prompt位置/窗口。
对已知位置的加法注入，可在请求提交前绑定向量、层、强度和位置表，无需外部教师逐token回调。
官方direct可走图内路径；实际吞吐、逐题向量绑定与当前项目模型/概率协议仍须实测。

首回答预测发生在最后prompt状态，后续是对应token的t−1状态；需要把预测idx转换成引擎selector坐标，
不能直接假设回答token序号等于hook输入行号。保存原始idx和引擎位置映射，并覆盖首token、EOS及padding验收。
当前项目环境不是已迁移完成的新版EasySteer fork，不能只写generation_positions就声称已接通。
Slerp也仍须显式实现/验收，单位归一化后的加法不等同于Slerp。

当前固定前缀搜索优先采用可批量teacher forcing的共同参考路径；无需先完成EasySteer自由生成迁移。
如果以后选择静态位置二次生成，再验收EasySteer的已知mask路径；原动态两阶段引擎改造不再是当前必需项。
官方接口证据见[方法分支](05_method_branches.md#41-easysteer可以按位置注入hf是当前实现选择)。

## 4. 八方案和参数保持不变

三个轴是T−S/T−R × 全回答预测位置/静态overlap位置 × 全局均值/逐题SV，共8方案。
每个方案都比较加法rho与Slerp alpha，各取[0.01,0.1,0.3,0.5]，全部单层50%/75%/100%。
当前28层模型映射为0-based 13/20/27；共192个非零候选，加一份共同无干预基线。
SV提取粒度/刷新与mask是否静态是不同问题，本轮仍冻结S0，不添加刷新频率搜索轴。

沿用共同T/R/S文本、过滤、尺度与训练侧select/confirm协议；原候选100题，已有共同有效55题，
新增末层后有效交集若改变，所有候选共用新交集并报告数量。
阈值在训练侧、生成mask之前冻结，保持同一协议，不增加逐候选阈值选优或测试集选型。

## 5. 留档、复用与绘图

每个mask文件至少保存：mask_kind=static_overlap、源question/response ID、源checkpoint/hash、
源prompt/回答token/hash、tokenizer和输出支持、学生/教师Top16来源与hash、k、阈值精确值、
逐位置O_src、requested_mask、实际mask、零向量原因、预测idx/引擎行映射、应用阶段与目标、来源版本。
结果另存向量/层/算子/强度及注入后Top16/overlap，不覆盖源O_src或静态mask。
旧动态轨迹的probe/正式分布及mask只能按历史标签读取，不充当无SV源回答的静态基线。

当前同前缀诊断默认画前3条：蓝线为整段无SV的源前缀overlap，橙线为固定mask注入后的同前缀overlap，
散点标实际注入，另画差值；保存PNG/SVG/CSV/合并PDF及hash。静态图不再要求每步probe。
若以后有二次自由生成，源轨迹与新轨迹token前缀不同，不能直接按idx相减后称为同状态配对DeltaOverlap。
老动态图及其蓝线“只关闭当前步、保留受控历史”的含义不改写成静态全程无SV。

## 6. 验收和实施状态

先完成静态mask来源/shape/hash、阈值边界、零向量、首token映射和加法/Slerp固定mask前向验收，
再用同一固定前缀评估全部候选；无需为当前主线增加在线教师交互或probe KV分支。
模型前向仍是因果的，后层历史干预对同前缀的影响保留，不能将中间层方案简化成只在输出logits上加向量。
教师Top16足以计算overlap；若训练需要新候选的教师概率，必须取得这些候选在同一前缀上的真实分数，
不能把已有教师Top16文件当作完整支持上的概率缓存。

现有源码中gate=overlap仍表示历史动态probe逻辑，尚未实现本协议的静态调度适配。
新规格使用static_overlap作方法标签，但不是可以直接传给旧Method的可执行配置。
原T−R任务的5条重放失败仍未解决，正式更新0；更改计划不代表旧任务已修复或训练已恢复。
