## 2. 当前执行开销与可优化点

当前后端为hf_batched_causal_gate，已有批量执行，并非逐条请求串行生成。源码显示：

- 每步先前向教师和学生probe；只对触发行再做正式学生前向，未触发行复用probe。
  忽略调度/输出头等时，学生侧约为(1+r)次完整前向，当前r约0.15，并非每个token无条件做两次学生前向。
- 正式触发分支目前从学生输入重新跑全部block，即使只在很深的block注入。
- select_cache对触发行的各层历史K/V执行index_select；probe虽只浅复制cache容器，正式分支仍有整段历史张量选取/复制。
- Python逐行计算门控和读取标量、逐行采样、逐步CPU日志搬运造成同步；Top16有重复计算。
- 拆批和重新组批通过保留mask/RNG后重新prefill重建KV，不是引擎原生的连续批处理和分页KV保留。

这些是源码可见开销；目前没有对各项做CUDA profile占比测量，不能将其中某项报为已测的主要瓶颈。
在线门控还将教师评分放进逐token采样依赖链，即使使用EasySteer，也不能省去同前缀的教师信息。

## 3. 修改源码可支持精确门控

EasySteer现有公开位置spec不能直接表达外部教师逐步overlap回调，但其fork已有GPU mask buffer和采样前入口。
固定fork commit为7837b07d21c0ddffd043a30001f2c5654290aec7，新增源码快照在本轮审计fork目录。
建议在独立引擎版本中实现，保留现有环境及HF参考路径。

| 源码位置（fork根目录相对路径） | 计划改造 |
|---|---|
| vllm/v1/worker/gpu_model_runner.py 的execute_model/sample_tokens | 增加probe→教师Top16→gate→正式logits的采样前阶段，最后只采样和推进一次 |
| vllm/model_hooks/steering/worker_manager.py 与graph/state.py | 按当前request行映射更新本步GPU gate buffer，覆盖排队/退出/重排映射 |
| vllm/model_hooks/steering/controllers/hidden_states.py | 在正确block输出坐标捕获/注入，支持加法及新Slerp算子 |
| 模型forward分段及paged-KV写入路径 | 复用注入点及之前计算，probe上层当前slot走临时分支，按gate提交正式slot |
| 教师调度/worker | 对相同实际token前缀增量评分，只回传或共享所需Top16及留档概率，不让教师独立采样 |

不能只在第一次forward以后更新mask：本步需正式重算受影响层，并使probe的当前上层KV不污染以后历史。
采样RNG只能由最终策略消耗一次；持久化向量、算子、强度和实际mask，学习重放使用相同条件。
GPU mask更新可与固定地址buffer/分段CUDA Graph配合，但两阶段整图、动态触发子批和教师等待的组合仍须实测。
不预先声称全路径可直接保持原完整CUDA Graph或达到某个提速倍数。

## 4. 单层网格可以进一步减少重算

新网格只在一个block输出注入。每步保存注入前该输出状态：probe仍需跑到完整logits；
触发后可以复用这个输出及下层KV，仅重算注入点之后的block、最终norm及输出头。
注入点所在block的attention/MLP已经完成，其K/V不受block输出注入影响，无需重做。
vLLM融合残差使用hidden/residual分开的表示；Slerp必须对完整残差流h操作，不能仅旋转hidden分支。

| 注入深度 | 28层模型 | 正式触发分支需要额外计算 |
|---|---|---|
| 50% | block13输出 | block14..27 + 最终norm/lm_head |
| 75% | block20输出 | block21..27 + 最终norm/lm_head |
| 100% | block27输出 | 最终norm/lm_head，无额外Transformer block前向 |

这是结构上的可复用范围，尚未实现或测出墙钟加速。输出头、教师、历史长度和调度仍会影响总时间。
末层输出注入不改变任何block已写入的K/V；在固定token前缀诊断中，未来状态也不受过去末层注入影响，
因此可批量计算该固定前缀的probe/gate再投影正式logits。自由生成时，改变采样token仍会改变后续前缀，
所以即使末层方案也必须逐步随实际token推进教师和学生，不能预用另一条无SV生成轨迹的mask。

## 5. 历史动态方案的拟议落实顺序（当前不执行）

1. 先做统一HF参考的批量Top16/门控、减少逐行同步，以及单层分段复用；优先末层专用路径，同时接入Slerp。
2. 与原参考比较全支持分布、实际mask、KV历史、保存/恢复与学习重放；沿用既定阈值，不以放宽检查换提速。
3. 用相同题、seed、长度/记录协议做小规模匹配性能基准，分开统计学生、教师、KV和同步时间，之后再决定引擎迁移收益。
4. 引擎版先实现末层路径，再扩展50%/75%的上层临时KV分支；通过验收后才用于正式结果。
5. 192候选优先按已固定的同前缀零更新协议运行，不对每项重做整批自由生成。
   teacher固定前缀缓存和身份匹配的提取池复用；中间层门控仍保持候选自己的受控历史。
