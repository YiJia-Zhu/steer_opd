# 主线代码框架逻辑

本文记录已确认的教师空间 **S−T／global／all + OPD** 主线，说明数据流、代码职责、推理与训练后端，以及缓存复用条件。实际执行范围与参数以[唯一实验计划](ablation.md)和冻结运行配置为准；本文用于解释框架。

截至2026-11-17，当前GPU实验为零更新的overlap参数搜索。OPD训练入口已接入verl并完成CPU接口核对，多卡训练尚未GPU验收或正式执行；独立评测为后续阶段。

## 1. 总体流程与后端职责

```text
一次性准备
  原1000题与700/300划分
    → 冻结教师T₀、初始学生S₀分别无SV生成参考回答
    → T₀读取两种回答，提取同层隐状态并池化
    → CPU构造教师空间S−T全局方向
    → 固定学生前缀，搜索层位／算子／强度，比较双overlap指标
    → 固定训练所用bank和注入参数

每个训练批次
  当前学生Sθ无SV生成                     [verl → 普通vLLM]
    → 重算当前学生无梯度logp              [verl → FSDP]
    → 教师注入固定S−T方向，沿学生回答评分   [独立EasySteer进程 → vLLM后端]
    → 跨tokenizer对齐，构造并冻结OPD优势   [CPU／无梯度张量计算]
    → 当前学生带梯度前向、反向、参数更新    [verl → PyTorch/FSDP]
    → 将新学生权重同步到rollout引擎        [verl]
    → 下一批重新生成

训练结束
  训练后学生无SV独立评测                  [普通vLLM]
    → 汇总准确率、训练成本和来源身份
```

| 组件 | 职责 | 使用位置 |
|---|---|---|
| vLLM | 批量生成、因果前缀评分、自动推理调度 | 准备阶段的普通生成；训练阶段的学生rollout；教师评分的底层引擎；最终学生评测 |
| EasySteer | 在vLLM推理路径上增加指定层capture与SV注入 | 教师方向提取、overlap候选评分、训练时受控教师评分 |
| verl | 编排rollout、评分桥接、学生更新、权重同步及checkpoint | 正式OPD训练 |
| PyTorch/FSDP | 学生无梯度logp重算、带梯度前向、反向传播及分布式更新 | 正式OPD训练的学生侧 |
| CPU处理 | 文本／tokenizer对齐、FP32池化、bank构造、双指标、文件提交与绘图 | 各阶段引擎调用返回后 |

EasySteer本身使用vLLM推理后端。当前准备阶段的普通生成也走EasySteer环境，只是设置`steering=False`。正式训练的学生rollout则由verl调用普通vLLM。

两套推理环境保持隔离：`.venv-easysteer`用于EasySteer固定fork，`.venv-opd`用于学生端普通vLLM与verl。反向传播由PyTorch/FSDP完成，推理引擎不承担学生梯度更新。

## 2. 一次性准备：回答、方向与选参

### 2.1 固定数据和初始回答

教师固定为Qwen3.5-35B-A3B，学生固定为Qwen3-4B。原1000题与700/300 Select／Confirm划分保持；每个采样请求seed均为42。

冻结教师T₀、初始学生S₀分别回答这些题目，得到教师参考文本`y_T0`和学生无SV源文本`y_S0`。已提交回答核验模型、prompt、采样配置、引擎身份及文件SHA后复用。

两批文本用于构造固定方向及零更新诊断。global方向使用全部1000题提取池，包含300题Confirm，因此Confirm是训练侧复核集；最终独立测试需另用评测集。

### 2.2 在教师空间提取S−T

同一个冻结教师T₀分别读取`prompt + y_S0`与`prompt + y_T0`。对每题，在指定教师block输出处取得完整hidden + residual，并计算保留回答token的均值：

```text
mu_S[i] = FP32_mean(H_T0(prompt_i, y_S0_i)的保留回答token)
mu_T[i] = FP32_mean(H_T0(prompt_i, y_T0_i)的保留回答token)
d_i     = mu_S[i] - mu_T[i]
d_global_raw = mean_i(d_i)
```

减法两项都处于教师隐空间。实现不涉及跨模型隐状态直接相减，也不能把学生空间T−S向量取负作为教师S−T。

提取规则如下：

- `sv_max_context_len=2048`包含prompt和strip后的回答，右截断后对全部保留回答token池化；仅跳过没有有效回答token的样本。
- 全部题目参与，不按正确性、生成截断或重复过滤。实际有效题集及覆盖率单独记录。
- BF16逐token状态仅在内存中处理，FP32池化；磁盘保存池化均值／范数、bank和身份，不保存逐token隐状态。
- 提取与注入在同一block输出处；0-based39层取final norm之前的block输出。

2048仅限制方向提取时读取的上下文。原始参考回答保留，正式生成与评分使用各自的长度配置。

### 2.3 固定前缀选参

当前只保留教师注入、S−T、global、all方案，搜索教师层19／29／39 × Slerp／additive × alpha 0.05／0.1／0.3／0.5，共24组。已有匹配结果经核验引用；旧0.2保留为历史结果。

两种算子使用相同的原始global均值差分基础：

```text
Slerp:   沿unit(d_global_raw)注入，alpha控制插值比例
additive: h_new = h + alpha * d_global_raw
```

additive系数只乘一次，无额外激活范数缩放。改变alpha或算子可共用同层bank；改变提取层需取得对应层capture与bank。

学生源文本与学生分布固定，EasySteer在教师侧注入后沿同一学生文本评分。CPU计算Top16最大一一前缀兼容匹配的`overlap`，以及Top16原始概率最大兼容质量的`P_overlap`，后者不重新归一化。

选参按Select题目等权Δoverlap，Confirm不参与排名。固定前缀指标用于筛选即时干预参数；学生参数更新数为0。正式训练前冻结选定的层、算子、alpha和bank身份，代码默认层29／Slerp0.1仍是准备值。

## 3. 正式训练：每批生成、评分、更新

当前代码准备值为全局batch16、100个更新批次、学习率1e-6，700题Select供学生更新。每批新rollout只做一次更新，`n=1`、`ppo_epochs=1`，使用固定注入强度。

训练准备布局是学生两卡承担FSDP与普通vLLM rollout，教师独立两卡承担EasySteer TP2；实际GPU绑定以正式训练冻结配置及验收为准。这与当前只用物理GPU2／3的参数搜索是不同阶段。

### 3.1 当前学生无SV生成

verl将当前学生权重交给普通vLLM，在当批题目上自由生成回答，保留实际学生token ID。学生rollout和之后的学生学习前向均关闭SV。

当前学生随更新变化，下一批使用新权重重新生成on-policy轨迹。正式训练配置为temperature=1、top_p=1、top_k=-1，每个请求seed42。

### 3.2 重算学生logp，教师沿同一回答评分

在本批参数更新前，verl先通过FSDP重算当前学生无梯度`old_log_probs`。随后将实际学生回答交给常驻的独立EasySteer教师评分服务。

教师使用自己的tokenizer重分词相同精确回答文本，在全部回答预测位置注入已冻结的S−T全局方向，取得观察token原生logp。教师沿学生回答做因果前缀评分，无需每批额外生成一份教师答案；评分接口为完成前向而生成的末尾辅助token丢弃。

教师权重、bank与注入参数在这条固定方向主线中保持不变；新的学生文本仍需重新评分。首预测使用prompt末状态，回答预测t对应`prompt_len - 1 + t`。

### 3.3 对齐、冻结优势、更新学生

学生实际采样ID保持。CPU按共同UTF-8安全边界构造文本span，将教师和学生在各span内的观察token原生logp分别取平均，再广播到学生token位置。

默认传统OPD的逻辑为：

```text
A_t = stop_gradient(mean_span(logp_T_SV) - mean_span(logp_S_current))
loss = -sum(valid_mask * A_t * logp_S_with_grad) / sum(valid_mask)
```

优势整体停止梯度，学生学习logp来自新的带梯度前向。EOS目标、padding、控制token及无法形成合法共同span的位置排除；整批没有有效训练token时拒绝更新。FSDP按全局有效token数归一化，随后完成一次参数更新。

verl再将新权重同步给学生vLLM，下一批重复上述流程。方向bank继续复用，无需每步重新生成初始参考回答或做capture。

默认传统OPD只需S／T两角色。可选CompassOPD会增加弱Ref和冻结初始学生锚点及对应评分，属于单独loss路线，细节见[实现说明](implementation.md#后续训练loss组件传统opdcompassopd)。

### 3.4 训练循环伪代码

以下函数名表示职责，用于说明调用顺序；实际入口与模块见第6节。

```python
# 一次性准备，可按组件身份核验复用
teacher_texts = generate_or_reuse(T0, questions, steering=False)
student_texts = generate_or_reuse(S0, questions, steering=False)
bank_by_layer = capture_and_pool_in_teacher_space(
    T0, student_texts, teacher_texts, layers=candidate_layers,
    max_context_len=2048,
)
chosen = screen_fixed_prefix_overlap(bank_by_layer, candidate_parameters)
freeze_training_plan(chosen)

# 正式训练：教师评分服务常驻，学生每批生成后更新一次
student = load_initial_student(S0)
teacher_scorer = start_easysteer_service(T0, chosen)
for batch in training_batches(select_questions, batch_size=16, steps=100):
    rollout = verl_vllm_generate(student, batch, steering=False, seed=42)
    student_logp_old = fsdp_recompute_logp(student, rollout, grad=False)
    teacher_scores = teacher_scorer.score_same_text(rollout)
    alignment = align_native_token_spans(rollout, teacher_scores)
    advantages, valid_mask = detached_opd_advantages(
        student_logp_old, teacher_scores, alignment,
    )
    student_logp_grad = fsdp_forward_logp(student, rollout, grad=True)
    loss = global_valid_token_mean(-advantages * student_logp_grad, valid_mask)
    fsdp_backward_and_one_update(loss)
    verl_sync_rollout_weights(student)
    save_checkpoint_if_due()

# 独立评测属于后续任务，使用已固定checkpoint和独立测试集
```

## 4. 为什么准备阶段和训练阶段都要学生无SV生成

两者在算法操作上相同：学生关闭SV，根据题目生成回答。它们承担不同职责：

| 对比项 | 一次性准备 | 每批正式训练 |
|---|---|---|
| 学生权重 | 固定初始S₀ | 当前Sθ，随更新变化 |
| 数据用途 | 给教师读取，构造固定S−T方向；用于固定前缀诊断 | 构成本批on-policy训练轨迹 |
| 执行频率 | 初始参考池生成一次 | 每个训练batch生成一次 |
| 后端 | EasySteer环境的vLLM，`steering=False` | verl调用普通vLLM |
| 更新后的处理 | 原回答及由其构造的固定bank继续保留 | 用新学生权重重新生成 |

第一批训练尚未更新时，两者在概念上可以重合。直接复用还需题目／prompt、checkpoint、tokenizer、采样配置、请求seed、引擎及代码身份全部满足同一科学合同，并有完整提交证明。当前两套生成缓存没有自动打通，不能只凭相同S₀和seed42直接互用。

## 5. 缓存与恢复边界

| 产物 | 可复用条件 | 需要重新计算的情况 |
|---|---|---|
| 初始T₀／S₀回答 | 权重、prompt、tokenizer、采样与引擎合同一致，SHA核验通过 | 上述生成条件改变 |
| 教师池化结果 | 教师权重、两份读取文本、层、提取长度及池化规则一致 | 新层、读取文本或提取协议改变 |
| global bank | 池化来源、有效题集与方向构造一致 | 来源或方向合同改变；alpha变化本身不使bank失效 |
| 无SV原生概率与对齐 | 完整前缀、模型、tokenizer及评分协议一致 | 模型或文本前缀改变 |
| 受控教师训练评分 | 完整前缀、冻结教师、bank、层、算子、alpha和训练评分合同一致 | 新回答或任一受控评分条件改变 |
| 当前学生学习logp | 每批由当前权重重新做带梯度前向 | 学生更新后不能沿用旧logp或旧计算图 |

准备及overlap阶段以整次`engine_call`为提交单元，完整返回后保存，最后原子写入带SHA清单的`complete.json`。没有完成标记的当前整批重算；已提交阶段核验后复用。

训练恢复以verl提交的模型／优化器／调度器／数据迭代checkpoint为准；评分缓存保存教师结果，不能代替学生参数断点。训练准备值为每10步保存checkpoint，最多保留1份。新的自由轨迹不能直接套用冻结S₀的overlap概率。

overlap阶段保存Top16 ID／原始logp与观察token logp。训练评分留档仅保存观察token logp及请求身份；Top16 overlap不进入OPD loss。所有阶段均不保存逐token隐状态。

## 7. 一次运行的耗时口径

以下依据RTX PRO 5000 72GB上的已提交运行记录，不含等卡时间。参数点耗时与完整训练耗时分开统计。

| 范围 | 时间 | 依据与限制 |
|---|---|---|
| 初始教师1000题回答 | 约84分钟 | 已测子阶段，教师较完整回答保留 |
| 初始学生1000题回答 | 约28分钟 | 已测子阶段，普通无SV源生成 |
| 新增教师一层capture与池化 | 约5–6分钟 | 已测子阶段，同层跨alpha／算子共用 |
| 上游齐全的一个1000题参数点 | 约22分钟，排期可按20–30分钟 | 已完成层19／Slerp0.1：campaign约20分钟，加逐点GPU验收约2分钟；包含700/300、无SV重放、双指标和图 |
| 从零准备并验一个参数点 | 约2–3小时 | 按已测子阶段合算，具体取决于可复用组件 |
| 完整100步OPD | 尚无GPU实测 | 不能从零更新参数点直接推算训练速度 |

计时来源：原1000题[教师生成](../outputs/step_3_overlap/ablation/T_Qwen3.5-35B-A3B_S_Qwen3-4B/OpenThoughts3-1.2M/shared/n1000_slerp0.1_layer26_seed42_v1/logs/attempts/reference_teacher_1794739096883761993/process.json)、[学生生成](../outputs/step_3_overlap/ablation/T_Qwen3.5-35B-A3B_S_Qwen3-4B/OpenThoughts3-1.2M/shared/n1000_slerp0.1_layer26_seed42_v1/logs/attempts/source_1794744160801784913/process.json)，以及层19／Slerp0.1的[已提交阶段日志](../outputs/step_3_overlap/param/T_Qwen3.5-35B-A3B_S_Qwen3-4B/OpenThoughts3-1.2M/shared/n1000_slerp0.1_S26_T19_seed42_st_all_global_v2/logs/progress.json)。

完整训练预算按以下方式估算：

```text
T_train = 初始化 + 100 × 平均单步时间 + checkpoint及其他开销
单步包含：学生生成 + 学生logp重算 + 教师评分 + 对齐 + 学生更新 + 权重同步
```

若单步为2分钟，100步主体约3.3小时；若为5分钟，约8.3小时。两者是预算假设，正式训练前5–10步实测后更新ETA。排期可先留半天；无缓存时另加一次性准备，独立评测耗时另计。
