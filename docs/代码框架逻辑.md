# 代码框架逻辑

静态 SV 先用冻结的 1024 题准备教师空间 S−T 和 overlap，再进入 OPD。动态 SV 直接从同一冻结题集开始 OPD，每步用当步回答重新构造教师空间方向。两个分支均冻结教师参数，只更新学生。

## 1. 共同参数

以下是当前新运行的默认值，已有实验以各自保存的配置为准。

| 项目 | 设置 |
|---|---|
| 教师／学生 | Qwen3.5-35B-A3B／Qwen3-4B |
| 自由生成参数 | **temperature=1.0、top_p=1.0、top_k=-1、presence_penalty=2.0** |
| 模板与长度 | 各模型原生chat模板，关闭thinking；题目prompt最多1024 token，生成回答最多16384 token |
| 准备数据 | 保留原1000题，同源补充24题；全部1024题同时用于SV、overlap和OPD，不划分Select／Confirm |
| 每个训练step | **32道题，每题4条回答，共128条回答，完成一次参数更新** |
| 随机种子 | 准备阶段每请求42；训练每题4条分别42／43／44／45；评测每请求42 |
| 训练预算 | 最多64个step；每轮32步，64步共两轮；学习率1e-6，AdamW |
| 裸学生评测 | step0、每16步及末步；默认0／16／32／48／64 |
| 模型checkpoint | 每16步及末步，默认保留16／32／48／64全部模型；优化器等恢复状态只保留最新完整一份 |

| 训练输出 | 项目`outputs/step_4_train/ablation/<模型组合>/<数据集>/shared/<运行名>/`；根目录为`/home/zhenning/data/working_tmp/steer_opd/outputs`，其他阶段路径不变 |

EasySteer使用vLLM作为推理后端。下文写“EasySteer”时，也在使用vLLM。学生的梯度计算和参数更新由verl中的PyTorch/FSDP完成。

## 2. 训练前准备

### 第1步：教师和学生分别生成回答

教师和初始学生分别回答这1024道题，均不注入SV。每题各生成1条回答，到EOS或长度上限结束。

**使用：EasySteer／vLLM，GPU推理。** 学生生成时一并返回Top16和实际生成token的logprob；隐状态在下一步单独提取。

### 第2步：教师读取两种回答，提取隐状态

同一个冻结教师分别读取：

- 题目＋学生回答。
- 题目＋教师自己的回答。

**使用：教师模型＋EasySteer capture，GPU前向。** 每份输入只读取前2048个总token，均值只计算保留的回答部分。这里提取的两份激活都来自教师模型。

### 第3步：构建并固定SV

CPU分别计算两份回答激活的均值，再相减：

```text
每题方向 = 教师读取学生回答的平均激活 − 教师读取自身回答的平均激活
全局SV   = 所有有效题目的方向再求平均
```

**使用：CPU。** 保存构建好的SV。后续训练持续使用同一份SV，不在每个step重新提取。

### 第4步：教师注入SV评分，计算全训练集overlap

教师按指定参数注入SV，重新读取第1步全部1024题的学生回答，计算观察token的logprob和Top16。学生侧使用第1步已有的原始概率。

**使用：教师EasySteer／vLLM在GPU评分，CPU计算overlap和P_overlap。** 当前只计算配置指定的一组参数及其无SV基线，整个训练池统一汇总，不设置选参集或复核集。历史参数搜索仍以原冻结协议留档。

这一步结束时，学生仍没有更新。准备回答用于SV和选参；训练会重新生成每批回答。

### per-sample消融：四条提取，原单条评分（已完成并归档）

上面第1—4步描述原global流程，每题一条准备回答；其overlap现已完成，该运行不热修改。per-sample及后续机制／参数实验先由冻结S0每题rollout 4条，分别使用seed42／43／44／45；整批提交后，冻结T0逐条读取并池化四条回答，四个池化值等权平均后减去该题原教师参考回答的池化值，每题只形成一个S−T方向。global沿用当前单条提取协议；两者的信息量差异在消融中明确披露。

**四条只用于方向提取，overlap继续沿原每题一条固定学生回答评分。** 原评分回答、学生Top16、教师无SV评分和静态mask在核验后可共享；单条提取bank及受控评分不能充当四条提取结果。新增协议通过437项CPU回归及师生GPU验收，16组消融已完成，执行时始终排除GPU2／3；实施、复用和计数以[ablation计划](ablation.md#提取与评分分开)为准。消融产物已统一迁至主outputs，源码快照保留在step6的metadata/implementation，隔离工作树已清理。旧OPD在完成2次更新后因UTF-8解码错误退出；2026-11-19修复对齐后已在tmux ste中以opd_n1024_project_outputs_utf8_v2重新启动。旧运行尚无checkpoint，新身份从初始学生重跑，训练超参数与SV保持一致。

## 3. OPD训练内部逐阶段拆开

### 第5步：先做step0评测，再完成第1个训练step

正式训练入口先评测初始裸学生，记录**step0准确率**。然后开始第1个训练step：

1. **学生生成**：初始学生通过普通vLLM回答当批32道题，每题4条，不注入SV；得到128条新回答及原始logprob。
2. **教师评分**：教师通过EasySteer注入固定SV，读取这128条回答，计算教师logprob。评分上下文默认24576 token，包含教师原生 prompt 和重分词后的完整学生回答。动态入口用 `--score-max-model-len`、baseline 入口用 `SCORE_MAX_MODEL_LEN` 调整此上限。
3. **CPU处理**：按共同文本片段对齐师生token，利用平均logprob之差构造训练信号。开启`--overlap-metrics`时，也在这里用本批师生Top16计算**更新前的overlap**；不额外生成回答。
4. **学生学习**：学生在verl／FSDP下读取同一批回答，完成**带梯度前向 → 反向传播 → 优化器更新**，得到第1步更新后的学生。
5. **同步权重**：把更新后的学生参数同步给vLLM，供下一步生成使用。

学生旧logprob直接复用本次vLLM生成返回的数值；FSDP保留用于学习的带梯度前向。

新 OPD 训练中，vLLM 确认学生采样到 EOS 并正常结束时，教师在完整回答后用自己的同名 EOS token 评分，终止位置单独参与 loss。Qwen3-4B 的 `<|im_end|>`（151645）对应 Qwen3.5-35B-A3B 的 248046，`<|endoftext|>` 则对应 151643 和 248044。后者也用作 padding，通过实际生成长度和结束信息识别。长度截断的回答只在有效正文位置计算 loss。Overlap 和 P_overlap 仍按共同正文位置统计。

训练对齐允许生成内容包含不合法UTF-8：保留实际学生token，教师对合法Unicode片段使用原生BPE、对损坏字节使用其原生单字节token，并核验师生完整回答字节完全一致。只将涉及损坏字节的共同span标为无效，后续合法span继续参与loss与overlap；显示文本中的反斜杠转义不作为模型输入。每步记录`alignment/invalid_utf8_bytes`和`alignment/invalid_utf8_trajectories`及有效覆盖率。静态消融默认仍严格拒绝不合法UTF-8，既有产物和提交身份不改写。

生成内容还可能包含未做NFC规范化的合法Unicode，例如`e`与组合重音。若教师常规重编码改写了原回答字节，训练对齐改用独立的原生BPE回答编码器副本，仅关闭该副本的normalizer，再校验完整字节完全一致。原tokenizer及prompt处理、实际学生token、静态消融的严格默认值均保持；不把规范化后的文本替换进训练。新plan记录`response_encoding_policy=native_bpe_without_response_normalization_v1`，受影响的alignment记录角色及策略，每步标量`alignment/verbatim_response_trajectories`记录发生次数。旧冻结plan不改写，恢复训练须使用新运行身份绑定已有完整checkpoint。

### 第6步：用更新后的学生完成第2步，并继续循环

第2步使用已经更新过的学生，重复同一流程：

```text
学生vLLM生成新回答
    → 教师EasySteer注入固定SV，沿新回答评分
    → CPU对齐、构造训练信号，并按开关统计overlap
    → 学生verl／FSDP前向、反向、更新
    → 同步新权重给vLLM
```

第3、4……步同样执行。**每个step重新生成学生回答、重新取得对应教师评分；教师权重和SV保持固定。**

### 第7步：完成第16次更新后评测

第16个step更新结束后：

1. 将第16步学生权重同步给vLLM。
2. 第16步的**裸学生**独立回答MATH-500的500题和AIME2025的30题，每题1条。
3. CPU使用math-verify对照标准答案，记录准确率。

**评测使用普通vLLM，学生不注入SV，教师不参与评分。** 后续在第32、48、64步及最后一步重复评测，并保存该步的学生模型。`SAVE_EVERY`默认与`EVAL_EVERY`对齐；模型版本全部保留，恢复状态只保留最新完整点。

训练overlap记录的是本次更新前的师生分布；评测准确率反映更新后学生独立答题的表现。两者分别记录。

presence penalty作用于生成采样；上述logprob、Top16和训练信号使用惩罚前的原始模型概率。

实验范围见[ablation计划](ablation.md)，指标算例见[overlap](overlap.md)，耗时见[运行时间](目前代码估计运行时间.md)。

### 动态 SV 的训练链路

动态训练沿用 step 0 题集、两卡分时和原有 OPD 目标。当前学生生成 32×4 条回答后释放两卡。冻结教师在同一个 EasySteer 引擎里，先关闭注入为当批每题生成一条参考，再读取学生回答和自己的参考回答。在教师隐空间逐题用学生回答平均激活减教师参考回答激活，跨题平均成本批方向。随后同一个教师引擎注入该方向，沿完整学生回答评分。教师再次睡眠后才进入学生梯度更新。[方向与池化定义](ablation.md#动态-sv)

动态请求绑定训练步和完整前缀，避免跨步复用评分。当前批请求和评分截面沿用 minimal_v1 的清理规则。eval 的题面、回答与 checkpoint 周期沿用现有训练设置。动态入口为 `bash scripts/run_dynamic_sv.sh --check`，未指定 `--run` 时只做 CPU 预览。[动态训练入口](../scripts/run_dynamic_sv.sh)

## 8. 运行、验收与留档细则

### 8.1 环境和手动入口

完整主线入口是[`scripts/run_full_pipeline.sh`](../scripts/run_full_pipeline.sh)。文件最前面集中配置SV与训练超参数，并注明可选值；默认教师空间S−T、global、all、Slerp0.1、教师第29层、1024题、32题/step、最多64步、每16步评测。`bash scripts/run_full_pipeline.sh --check`只做CPU预览；`bash scripts/run_full_pipeline.sh --run`依次完成师生准备回答、SV提取、全训练集overlap和OPD训练。当前OPD支持global/all，per_question/static_overlap仍使用单独overlap入口。

`bash scripts/run_full_pipeline.sh --prepare-data`可单独在CPU保留原1000题并同源补充24题，排除MATH-500/AIME2025中的完全相同题目，冻结到`n1024_all_train_seed42_v1`。原1000题缺失时只读`output_remote`；首次`--run`也会先准备题集。新题集保存`train_ids.json`，不生成`split.json`。准备产物写入项目`outputs/`的新参数身份，训练也默认写入项目`outputs/step_4_train/`；训练核验bank与1024题源SHA、题目ID摘要一致。修改参数会形成新准备身份；同参数再次`--run`复用已提交阶段，并从最近完整checkpoint恢复。`TRAIN_RUN_NAME`可指定新的训练身份；更换输出根目录时使用新名字，原冻结请求不覆盖。模板hold保留。

EasySteer固定前端`baecd9698f32aadef68b41536f3db477b513a0d7`、fork `7837b07d21c0ddffd043a30001f2c5654290aec7`及vLLM 0.29.0基座，身份见[源码清单](../ref/easysteer_runtime/manifest.json)。verl固定revision `61adb0c7eb90730306e7794c2bf248331211e657`；Rethinking兼容参数参考revision `ac26e38d6f1572eb027597b48a9f4e01f6915ef8`，必要适配写入plan的`rethinking_defaults`。两套Python环境隔离，不改共享环境或下载模型权重。

### 8.2 GPU验收与capture预算

使用spawn创建引擎，编译器／CUDA头文件匹配torch CUDA版本；TP>1关闭FlashInfer autotune，纯文本Qwen3.5跳过图像／视频预热。引擎初始化限时600秒，生成／评分不沿用此限时。保留自动调度和CUDA Graph，不人工限制max_num_seqs或图尺寸。

| 检查 | 当前约束与解释 |
|---|---|
| 默认验收路径 | `HF_PARITY=0`仅EasySteer师生自检；显式设1才增加HF跨后端数值参考，无自动HF降级 |
| 严格数值检查 | 观察token logp平均绝对差≤.05、最大≤.2；Top16 ID并集上的截断总变差≤.03；HF激活相对L2≤.03；学生零强度／移除恢复容差1e-5。阈值不因失败自动放宽，截断指标不代表完整词表一致 |
| 教师漂移 | Qwen3.5 GDN不支持当前batch-invariant；教师无SV分数单次冻结，重复漂移单独记录，不自动扣除；学生重放及显式HF对照保留严格检查 |
| 原生支持 | 学生151669、教师248077个已定义ID；补齐head行被裁剪。原生Top16按引擎rank提取，额外观察token不能替换第16项，无概率hook／完整词表RPC |
| capture内存 | host按全部保留BF16行及标签计算；device按实际调度token、层宽／层数及选择／转换工作区计算，再留25%与16 MiB余量；staging／fetch为16 MiB。预算写入`capture_budget.json`，不预先分配满上限 |
| 通过凭据 | 绑定代码、checkpoint内容、层／强度／算子、teacher TP及有效采样配置；配置改变或文件损坏拒绝混用；CPU通过不代表新GPU路径通过 |

### 8.3 指纹、存储API和图表

[checkpoint_identity.py](../src/steer_opd/checkpoint_identity.py)首次流式hash权重shard、config与tokenizer；之后按inode／大小／mtime／ctime复用，最近两秒写入的文件仍重hash。EasySteer指纹包含payload SHA、scale、layer、selector、algorithm和normalize。固定前缀评分关闭prefix caching，普通无SV生成按支持允许缓存；完整prompt评分与capture按上游规则跳过前缀读取，保证逐位置记录完整。

[artifact_reuse.py](../src/steer_opd/artifact_reuse.py)用`metadata/artifact.json`登记合同／提交／SHA，用`metadata/reuse.json`冻结descriptor SHA、artifact_id与owner；step3的upstreams和step6的source_index汇总实际来源。无完成标记则整批重算，损坏或冻结引用改变则报错。目录名不代替科学身份，旧已完成参数名由`historical_run.json`防覆盖。历史路径解析与迁移凭据见[输出结构§8](../输出结构.md#8-已完成100题1000题的实际迁移)，原始冻结记录不改字节。

候选结果的默认Parquet/Zstd、64条分片及其他格式集中见[输出结构](../输出结构.md)。设置`CANDIDATE_TENSOR_FORMAT`或`--candidate-tensor-format`选择`parquet_zstd`／`npz_compressed`／`npz`／`pt`／`pt_gzip`；旧`CANDIDATE_TENSOR_COMPRESSION`、`--candidate-tensor-compression`与`none`／`gzip`别名仍兼容。`StageCheckpoint.load_tensors(keys)`恢复完整记录，`load_tensor_fields(keys, ['overlap', 'P_overlap'])`可只解码指定题目／字段，但仍校验完整提交文件SHA；实现见[tensor_checkpoint.py](../src/steer_opd/tensor_checkpoint.py)和[tensor_archive.py](../src/steer_opd/tensor_archive.py)，Parquet依赖`pyarrow==24.0.0`。旧PT／PT-gzip按原`stage_input.json`读取，同一旧身份下不能切换格式覆盖。格式性能样本与限制见[格式基准](../audit/step3_format_comparison_20261118.json)、[双环境无损核验](../audit/columnar_checkpoint_support_20261118.json)。

源双指标只计算一次并保留SHA；阈值在Select有效题集校准，strict-<／nextafter规则保持，单一gate_metric控制mask。源、无SV重放和候选差值分别保存。图表按overlap／P_overlap分别生成前3条PNG／SVG／CSV／PDF：蓝线无SV重放、橙线候选、红点实际注入，差值单位pp；未评分保持NaN。教师`native_steering_mask`表示真实注入，学生坐标`steering_mask`仅用于映射展示。EasySteer逐token实际扰动范数尚未接入，`relative_perturbation_available=false`；HF参考能记录。

每位置Top16基本记录为16个int32 ID、16个FP32 logprob和1个观察token FP32 logprob，约132字节；文本、容器与元数据另计。当前监控和sampled-token loss不要求完整词表概率缓存。

### 8.5 最小保留策略

新配置默认`retention_policy=minimal_v1`、`checkpoint_retention=all_models_latest_state_v1`，新训练plan为v8。前者清理过程数据，后者保留所有保存点的模型并只保留最新恢复状态。无新字段的历史冻结运行继续按原协议读取；本次不批量清理现有outputs，也不改变正在进行的备份。静态overlap／参数实验的step1、step3结果仍按原协议保留。

| 数据 | 保留期限 | 下游使用 |
|---|---|---|
| 题目、划分、SV bank／尺度／有效题集、配置和模型／代码SHA | 长期 | 新批次训练及恢复 |
| 新建capture的`pooled.pt` | 所需reader的bank全部提交并校验后清理 | 只用于构建SV；保留退休凭据及原pool SHA |
| 当前批实际token IDs、对齐、NPZ请求、教师观察logprob及Top16 | `scorer/batch/`临时保存；有限梯度更新和标量提交成功后释放 | 当前批loss／overlap及同请求重试 |
| 学生Top16、逐轨迹overlap明细、训练rollout原文 | 当前批工作区 | 更新提交后清理，标量长期保留 |
| 训练内评测回答 | 每次 eval 保存一个 UTF-8 JSONL | 每行仅 `question_id`、原题面 `question` 和完整回答 `text`，保留完整推理、换行和最终回答。按冻结题号校验 MATH-500 的 500 条和 AIME2025 的 30 条后原子写入 |
| 每step loss、梯度、学习率、回答长度／多样性、overlap及阶段耗时；定期准确率 | 长期 | 曲线、进度和结果解释 |
| 学生模型checkpoint分片、配置及tokenizer资料 | 每16步及末步的版本全部长期保留 | 评测与模型比较；保留`model_checkpoint.complete.json`及SHA |
| 优化器／scheduler／RNG／dataloader状态 | 最近一份完整提交 | 恢复最新训练；新保存点完整提交后清理旧点的恢复状态 |
| overlap当前状态／worker控制回复 | 实时覆盖／消费后释放 | 当前进度；标量历史另保存在TensorBoard及训练日志 |

[sv_retention.py](../src/steer_opd/sv_retention.py)只清理本运行新建且在capture提交中显式标记minimal的pool，不删除共享owner或历史导入产物。先核验bank，再写带摘要的`metadata/pool_retirement.json`并同步凭据，最后删除pool；原capture的complete／descriptor字节与artifact_id保持不变。合法退休须同时验证原身份和保留bank的完整SHA，缺失pool且无凭据、凭据损坏或bank损坏都会拒绝复用。编排优先解析完整bank；同层改alpha可跳过已退休pool。需要新层、新交集或重新构建bank时，退休pool不能再充当可读取缓存，须在新参数身份下重新capture。

[训练retention.py](../src/steer_opd/training/retention.py)用plan绑定的owner约束批次工作区，清理前确认教师休眠且学生更新成功。失败批次在本次进程中保留供重试；重启后从最后checkpoint重放，旧临时区按owner检查后释放。清理使用目录更名隔离，可继续收尾中断的删除；遇到外部链接或错误owner立即拒绝。原始token IDs也随旧批清理，因而不提供该批逐token事后回放。

checkpoint先同步所有rank文件及目录，校验模型／优化器／extra_state及数据进度，再提交完整SHA清单`checkpoint.complete.json`、模型清单`model_checkpoint.complete.json`与独立的`latest_complete.json`。关闭上游提前轮换；新完整点提交后，先核验旧模型，再写入`state_retirement.json`并同步，最后只删除旧点的`data.pt`、优化器和extra_state分片。模型权重和配置始终保留原字节。清理中断可按退休凭据重试；损坏、外部链接或身份不符会拒绝清理。没有明确新策略标记的历史／外部源不自动转换。

`latest_complete.json`只指向可恢复训练的最新完整点；旧保存点用于模型评测，已清理的恢复状态不能用于继续训练。已有完整checkpoint约46.4 GiB，保存时需要新旧完整状态的周转空间，模型历史占用另计；每次保存前继续检查目标文件系统和用户quota。新增SHA／同步成本尚未做GPU运行计时，CPU检查不能替代新路径的GPU验收。

### 8.6 训练目录与用户配额

后续step4训练默认使用`configs/ablation.json`中的`train_output_root=outputs`，即`/home/zhenning/data/working_tmp/steer_opd/outputs`，解析到`/local_nvme/data/zhenning/working_tmp/steer_opd/outputs`。plan冻结为展开后的绝对路径；训练日志、准入凭据、当前批工作区、训练专用parquet和完整checkpoint均位于该运行下，SV bank与原始题目仍从各自原路径读取。`--train-output-root`可覆盖训练根目录，旧`~/steer_opd_outputs`仍支持显式指定及已有checkpoint读取；静态阶段的路径约束不变。旧outputs和冻结运行配置不移动或改写，更换根目录时使用新训练身份。

[storage.py](../src/steer_opd/training/storage.py)在启动前和保存checkpoint前，按实际目标目录的挂载点检查文件系统空间与可见用户quota，取两者较小值。原home训练目录的用户配额上限约137 GiB，2026-11-19检查时剩余约73.1 GiB，低于新训练96 GiB预算加余量后的98.92 GiB要求，因此旧启动停止在OPD之前。当前默认目录已改回数据盘；空间读数会变化，正式启动仍须按新目标目录重新检查。
